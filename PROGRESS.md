### Real bug found and fixed: date-formatting hydration mismatch
- [x] Caught by an actual `pageerror` during testing, not invented: React threw a hydration-mismatch warning because `new Date(...).toLocaleString()` (and several sibling `toLocaleDateString`/`toLocaleTimeString` calls) were passing `undefined` as the locale argument — which still depends on the *runtime's* default locale, so Node's server-side render and the browser's client-side render produced visibly different text ("24/08/2026, 19:00:00" vs "24/8/2026, 7:00:00 pm") for the exact same `Date`. Passing explicit format *options* without pinning the *locale* doesn't fully close this — confirmed by finding it was still possible even on calls that already had options.
- [x] Fixed at the root: added `formatDateTime`/`formatDate`/`formatTime`/`formatDayMonth`/`formatMonthYear` helpers in `src/lib/date-utils.ts`, all pinned to an explicit `"en-US"` locale, and swept every one of the 13 call sites across the app (patient/doctor appointment views, admin leave dates, the booking wizard, the calendar widget, the notification bell, and the outbound email templates) onto them — closing the mismatch class everywhere, not just where it was first observed, and standardizing how dates look across the whole app as a side benefit.

### New feature: standalone Symptom Checker (`/patient/symptom-checker`)
- [x] A self-serve "what might this be" tool, separate from booking: a patient describes symptoms (free text or category-grouped quick-add chips) and gets up to 5 possible conditions with urgency, explanation, and a recommended next step, plus a prominent "not a medical diagnosis" disclaimer and a straight line to book an appointment.
